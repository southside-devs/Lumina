------------------------------------------------------------Mobile app------------------------------------------------------------

You are building the complete production frontend for **Lumina**, a Crime Intelligence & Analytical Platform (KSP CIAP) for the Karnataka State Police, deployed on Zoho Catalyst. The stack is React 19 + Vite, no TypeScript, no Tailwind. All styling is inline CSS using CSS variables defined in index.css.

---

## DESIGN SYSTEM

Dark intelligence theme — command centre aesthetic, not SaaS startup.

CSS variables (defined in :root on index.css):

- --bg-primary: #0d1117 (page background)
- --bg-surface: #161b22 (cards, sidebar, topbar)
- --bg-elevated: #1c2333 (inputs, dropdowns, hover surfaces)
- --bg-hover: #21262d
- --border: #30363d
- --border-subtle: #21262d
- --text-primary: #e6edf3
- --text-secondary: #8b949e
- --text-muted: #484f58
- --accent: #1f6feb (primary blue — authority)
- --accent-hover: #388bfd
- --accent-bg: rgba(31,111,235,0.15)
- --danger: #da3633
- --danger-bg: rgba(218,54,51,0.15)
- --warning: #f0883e
- --warning-bg: rgba(240,136,62,0.15)
- --success: #2ea043
- --success-bg: rgba(46,160,67,0.15)
- --font-sans: 'Inter', system-ui, sans-serif
- --font-mono: 'JetBrains Mono', monospace

Load Inter + JetBrains Mono from Google Fonts in index.html.

Global: box-sizing border-box everywhere, no margin/padding resets except zero. Scrollbar styled: 6px, --bg-surface track, --border thumb.

Layout: #root is display:flex, height:100vh, overflow:hidden — sidebar + main column (topbar + content).

Animations: fadeIn (opacity 0→1, translateY 8px→0, 0.25s), pulse-live (opacity 1→0.4→1, 2s infinite for live indicator bar), spin (360deg for loading spinner).

- Calls `GET /api/accused?repeat_offenders=true&limit=50&offset=N`
- Paginated table: Name, Arrest Count (sorted desc), Gender, Occupation
- Each row has View Profile button → `/accused/:ROWID`
- Header stat: total repeat offenders count from dashboard overview
- Empty state: "No repeat offenders found. This filter shows accused with 2 or more arrests."

### `src/pages/AIQuery.jsx`

- Chat interface: scrollable message list + input bar at bottom
- Assistant bubble style (left-aligned, --bg-elevated background)
- User bubble style (right-aligned, --accent-bg background)
- 5 canned demo Q&A pairs (e.g. "Show theft trends in Mysuru", "Which districts have highest assault rates?", "How many FIRs were filed last month?", "Who are the top repeat offenders in Bengaluru?", "Show crime trends for Narcotics")
- Typing indicator (animated dots) while "processing" (500ms delay)
- "Preview" badge in header, disclaimer: "AI Preview — Live QuickML RAG integration in progress"
- Send on Enter key or Send button

## API UTILITY (`src/utils/api.js`) — COMPLETE REFERENCE

Base URL: `/api` (proxied via Vite to Catalyst)
All requests: credentials: 'include', Content-Type: application/json
Error shape: `{ status: "error", message: "...", details: [] }`
Success shape: `{ status: "success", data: ..., meta: { total, limit, offset, has_more } }`
Primary key on all records: `ROWID` (integer)

Endpoints to expose:

````js
firApi.list(params)         // GET /firs?limit&offset&station_id&crime_group&status
firApi.search(params)       // GET /firs/search?crime_group&date_from&date_to&station_id&lat_min&lat_max&lon_min&lon_max
firApi.get(id)              // GET /firs/:id  → includes victims[] and accused[]
firApi.create(data)         // POST /firs
firApi.update(id, data)     // PUT /firs/:id

accusedApi.list(params)     // GET /accused?limit&offset&repeat_offenders=true
accusedApi.get(id)          // GET /accused/:id  → includes cases[]
accusedApi.create(data)     // POST /accused
accusedApi.update(id, data) // PUT /accused/:id

victimApi.list(params)      // GET /victims?limit&offset&fir_id
victimApi.get(id)           // GET /victims/:id
victimApi.create(data)      // POST /victims

caseAccusedApi.create(data) // POST /case-accused  { FIR_ID, Accused_ID, Involvement_Type }
caseAccusedApi.delete(id)   // DELETE /case-accused/:id

districtApi.list()          // GET /districts?limit=100
stationApi.list(districtId) // GET /stations?limit=300&district_id=N

dashboardApi.overview()     // GET /dashboard/overview
dashboardApi.trends()       // GET /dashboard/crime-trends
dashboardApi.districtSummary() // GET /dashboard/district-summary

riskApi.list(params)        // GET /risk-scores?limit&offset&district_id&crime_type
FIR POST required fields: Station_ID (int), FIR_Number (string), Date (YYYY-MM-DD), Crime_Group (enum), Latitude (float 11.5–18.5), Longitude (float 74.0–78.5)
Accused POST required: Name
Victim POST required: FIR_ID, Name
Multi-step FIR workflow: POST /firs → save fir_id → POST /accused → POST /case-accused {FIR_ID, Accused_ID} → POST /victims {FIR_ID, Name, ...}
````
